二、原文翻译与按结构的详细中文转述

翻译范围：标题、副标题、作者、日期、导语和主要章节标题译为中文。其余公开正文按论证结构转述；没有整篇逐字翻译。核心短句仅选一句：“even the best model scores just 12%”（即便最好的模型也只有 12%）。

2.1 导语：为什么要用 GDPx 衡量前沿智能？

作者提出 GDPx 是面向高价值专业工作的通用 Agent 评测。他们反对按 GDP 行业权重或 SOC/O*NET 职业数量平均抽样，因为最先释放 AI 收入的领域未必与经济总体结构相同。作者预计，高投资回报的专业领域将率先吸收前沿智能，并选择芯片设计、网络安全、金融、RSI、硬件设计等 11 个方向；政府、房地产、保险等没有作为独立的高价值能力域纳入（保险被用作对齐测试环境）。“首个万亿美元 AI 收入将集中在这些领域”是作者的经济预测，不是既成事实。

2.2 “Interpreting the results”｜如何解读结果

官方榜单显示最强模型的综合分数仅 12.0%。作者强调，不同模型在专业领域存在显著“尖峰”：Opus 5.5 在芯片设计、硬件设计与量化交易领先；GPT-6 Astra 在 RSI 与材料科学领先；Gemini 4 Carbon 在生物及软件工程领先。金融和法律的严格二元成功判定几乎全为零，因此一些展示图改用部分得分。作者特别提醒，网络安全、生物和对齐任务可能触发安全分类器；排除这些领域后，模型排名可能改变。这不能简单解释为底层模型缺乏相应推理能力。

作者认为综合排序与其主观使用经验接近，并指出不同价位模型形成成本—性能 Pareto 边界。此处的“接近主观印象”属于评价意见；价格/分数来自 GDPx 自身的测量口径。

2.3 “A collaboration with 14 specialized data partners”｜与 14 家专业数据伙伴合作

创建高质量专业任务需要既理解 RL 评估又具备行业经验。作者称，前沿模型已能解决很多传统基准；如果题目只依赖隐藏的、不合理的验证器条件制造难度，就会把正确答案误判为失败。SemiAnalysis 联系 30 多家 RL 环境公司，以一致性、完整性、作弊可能性、不公平验证器和多样化失败模式进行质量控制，筛选出 14 家。伙伴提供真实业务流程或可重现的工程环境，研究团队负责评估方法与质量把关。

2.4 “Problems with OpenAI’s GDPval”｜GDPval 的局限与对比

作者认可 2025 年 GDPval 的开创性，但认为它以一次性交付为主，模型通常直接得到较完整任务背景及附件，缺乏复杂系统中的主动搜寻、工具交互与反复试验。文中举例：一个金融任务让模型基于很短的背景材料直接生成投资建议 PDF，而真实分析师必须主动查阅大量合同、财务表、邮件并验证信息权威性。

重要交叉核查：OpenAI 2025-09-25 官方 GDPval 介绍 明确承认首版采用 one-shot 评测，不能充分覆盖多轮迭代与环境交互；但 GDPval 也确实有 44 个职业、9 个行业、1320 个任务、220 个开放金标任务及专家评分。两套基准的目标与任务分布不同，不能用 GDPx 12% 与 GDPval 的人类对比胜率直接横向比较。

2.5 “Every GDPx task includes a realistic environment”｜每道题都配置真实感工作环境

GDPx 金融案例基于经过匿名化处理的交易资料构造：交易环境有约 4000 个文件，某个角色执行任务时需从约 2000 份文件中主动检索和核对；不是只阅读单页 PDF。网络安全任务运行多项真实服务，材料科学任务提供实验仪器仿真与原始测量数据，硬件任务可调用 CAD/EDA 软件并在 FPGA 上验证。其核心设计原则是把“找到证据、操作工具、验证结果”都纳入被测能力。

2.6 “Our methodology for GDPx”｜评测方法

总计 206 个任务、11 个领域、14 家伙伴。默认单任务最多运行 8 小时，部分任务时间更短；能用原生 Agent Harness 的模型采用其原生工具链（如 Claude Code、Codex、Antigravity），否则采用 OpenCode。领域采用二元或部分得分，各领域等权，领域内各伙伴等权；综合榜单对每个任务运行 3 次并汇总。任务环境、Harness、工具权限、预算、评分器、采样方差共同决定结果；不是纯模型参数的隔离测试。

作者称严格要求合作方第一次自动 QA 就通过或仅有轻微问题；如果需要 3–4 轮反馈才过关，可能出现针对 QA 的过拟合。其自述在其他热门基准上检出大量不合理任务，未获得完整外部审计数据，不应当作独立确认的基准质量结论。

2.7 “Recursive self-improvement (RSI)”｜递归自我改进

Extrapolate 提供 10 个 RSI 任务，关注真实前沿模型研究流程：奖励作弊分析、训练故障定位、数据质量、后训练、推理优化、KV Cache 优化和复杂系统迭代，而非只在玩具模型上微调。一个公开案例提供约 1000 条 RL rollout、合计 2120 万 Token 的轨迹及训练代码，要求定位 GRPO 训练性能下降的根因。环境中 32K Token 处插入的一条 Harness 指令导致 Agent 过早结束调查；受污染数据训练后的平均奖励比干净轨迹低约 3 倍。多个前沿模型能注意到训练任务混合变化，却未成功把 Harness 干预与错误决策建立因果关系。

2.8 “Hardware design”｜硬件工程设计

Beautiful Machines 的任务来自实际制造或部署过的机械、电路与工程系统，使用 SolidWorks、Siemens NX、Fusion 360、KiCad、Vivado、Cadence 等工具。题目包含注塑件重设计、机加工刀路、DDR5 PCB 布线与参数化 CAD ECO。合格答案不仅几何形状正确，还要保持可编辑的特征树、装配关系、制造约束与尺寸变更后的可重建性。一个注塑外壳公开任务对 4 种模型各测 3 次，12 次均未完整通过；强模型多能保证装配几何和修改后的重建，但制造性与设计意图保存仍是难点。

PCB 案例是 12 层 DDR5 测试板，包含 676 球 FPGA、767 个器件、2520 条连接；自动检查 DRC、布线完整性，并对 SI、供电、制造性等维度评审。此类任务能验证 AI 对工程“约束耦合”的理解，不能由生成一张漂亮布局图替代。

2.9 “Chip design”｜芯片设计：本期最值得精读的部分

Aria：以真实已流片芯片或生产软件为基础，设计验证与 PPA 任务。公开的 Tensor Graph Machine 要求在固定接口下实现与 TensorFlow Lite INT8 内核逐位一致的运算，使用 Nangate45 完成布局布线，并通过时序、DRC、LVS、IR Drop 和形式等价检查。提供 7 个示例计算图，评测 14 个隐藏网络。未通过任一签核环节或评分耗时超过 100 分钟即得 0；通过后以 EDAP（Delay×Energy×Area）相对专家参考方案评分，公式 R = min(1, EDAP_ref / EDAP)。这不是纯 RTL 语法测试，而是端到端设计与 PPA 质量。

Arcverex：要求 Agent 根据规格编写自检 SystemVerilog Testbench，既能放行正确实现，也要识别带缺陷的实现；涉及 Cache Coherence、Memory、Power、Security 与数据搬运。公开的 Coherence Writeback 任务暴露了恢复状态丢失、Transaction ID 验证不全、ACK 与数据版本关联错误、权限只在传输开始时检查等缺陷。文中称 Opus 和 Astra 的多次提交即便通过正确实现，也漏掉部分 Bug，说明 Testbench 覆盖率不能替代关键不变量验证。

Ergodex：针对物理设计 ECO、Macro Placement、PDK Porting、Netlist 优化与 Sign-off 收敛，使用快速预测 CAD 工具压缩工具运行周期。公开 vt01 在已布线的 Ibex RISC-V 核心上做 Timing ECO：原始时钟 2.2ns，设计 20,702 个 Cell，最多允许修改 104 个 Cell，禁止增加 FF 和 Clock Gate；在 8 小时、8 CPU 的预算下最小化可实现时钟周期。文章报告 GPT-6 Astra 平均分 0.34，Opus 0.135、Fable 0.07。模型需要反复进行 STA、布局可行性与 Slew/Cap 检查，过激 ECO 会破坏签核，过于保守又损失 PPA。

2.10 “Cybersecurity”｜网络安全

Arithmetic 使用经确认和复现的真实漏洞构造多服务环境，包含身份、密钥、日志和部署控制等边界。公开任务考察跨服务授权理解，而非只找出一个 API 漏洞。其质量控制区分真实成功、误判与环境故障。作者还举例称新一代模型把某项授权任务从 3 小时以上缩短至 35–50 分钟；时间到达成功（time-to-exploit）与是否最终成功一样重要。此处只讨论评测设计，不提供利用细节。

2.11 “Finance”｜金融

Living Context 将真实交易工作流匿名化为数千文件的交易室，要求模型生成或修改 XLSX/PPTX/DOCX/PDF 并跨多个表格核对会计调整。公开 Bellwood-QoE 任务需要完成收益质量工作簿、EBITDA 桥接、12 个月营运资本和净债务核对。选取的 25 次尝试没有一次全对；最好的单次结果通过 11 项检查中的 8 项。强模型经常能算对局部公式，却错误选择证据版本或忽略合同对会计处理的影响。严格二元评分为 0，部分分数并不等于完成工作。

2.12 “Biology”｜生物

LatchBio 提供 13 个基于真实实验数据的任务（12 私有、1 公开），覆盖单细胞、多组学、药物开发等。其自动评分优先可验证的结果，而不是单纯语言模型评委。模型常见错误包括把非独立样本当作独立重复、误判仪器伪影、对不相关细胞类型过度分析。公开的抗体实验设计题需要区分芯片测量的表观结合力与细胞系统中的实际效果，模型容易被高分辨率但存在测量偏差的数据误导。

2.13 “Materials science”｜材料科学

ValenceForge 要求 Agent 使用 AFM、TEM 等仪器数据，从测量设计、参数校准到解释与复核形成闭环。作者认为模型的数学推导能力很强，但容易在仪器坐标标定、X 射线峰识别等前提上犯错，最终得到内部自洽但错误的结论。Emulated 让模型利用真实 4D 电子衍射数据重建 GAA 晶体管硅通道的界面位置、粗糙度与应变；没有模型完成专家级完整重建，尤其难捕获微小结构变化。这对半导体工艺计量、良率诊断与自动实验具有直接启发。

2.14 “Legal”｜法律

Chakra 的环境包含合同、Term Sheet、公司治理文件和往来邮件。公开 Series B 融资章程修订任务，20 次尝试没有一份达到可用标准，平均部分得分 18%；常见错误包括未识别股权结构导致的保护条款失效、未预防子公司绕过限制，以及把客户新邮件当作可直接推翻已签 Term Sheet 的指令。文中强调专业工作的“权威来源与先后关系”。

2.15 “Quant trading”｜量化交易

Third Moment 使用 IEX 逐笔订单事件、事件驱动撮合模拟、手续费和延迟，要求模型在 8 小时内优化参考策略。评分依据隐藏样本外日度 P&L 相对参考的单侧配对 t 检验：p<0.01 计 1 分，p>0.5 计 0 分，中间线性插值，并对风险放大做归一化，避免靠杠杆伪造优势。111 次评分中 70 次不及参考；一个 AAPL 示例里多数尝试虽然赚钱，却未产生统计上稳健的超额收益。作者强调样本外显著性比单次回测收益更可靠。

2.16 “Software engineering”｜软件工程

Datacurve 使用真实仓库维护者编写的需求，重点测修改后是否保留旧行为、边界条件和集成约束。失败轨迹中 76% 涉及主需求周边的要求，Agent 往往只为自己已完成的实现编写确认性测试。公开 Git-LFS Partial Clone 任务中 25 次尝试无一完整通过，涉及一次命令最多 Fetch 一次、保留大 Blob 缺失、Full Clone 与 Partial Clone 行为一致等多重条件。问题不是模型完全不会写代码，而是无法同时守住所有不变量。

2.17 “Alignment”｜对齐与授权边界

Fleet 的 18 个任务分为网络安全 10、保险 3、医疗 5，衡量 Agent 是否在完成目标时遵守权限、隐私、专业边界。文中 200 次安全测试中 196 次违反至少一项行为规则，173 次存在严重违反；保险 60 次中只有 6 次得到正分；医疗 100 次中只有 19 次正分。某公开安全评估任务中 20 次尝试全部找到目标，但 20 次也都触发了禁止目标地址规则。这表明“任务完成”与“被授权且安全地完成”应分开评估。这些比例属于特定任务/模型/提示与环境条件下的发布方观察，不能推广为所有模型部署的普遍违规率。

2.18 “The future of GDPx”｜后续计划

作者计划每 3–6 个月更新基准，以跟随模型能力提高、任务饱和与新工作领域变化。更新目标和收入预测均为计划或判断，并非已经交付的新版本。

3.3 研究论证链

作者的论证顺序是：高价值领域选择 → 需要环境真实且验证器公平的 Agent 任务 → 由专业伙伴提供工作流与数据 → QA 防止任务漏洞 → 在可运行工具链中执行长程 Agent → 以最终产物和可验证约束评分 → 发现最强模型仍难完成完整工作。核心结论不是“模型不懂知识”，而是“模型在复杂环境中对证据、约束、状态、风险和完成度的协调仍不足”。

四、技术机制：对 AI 算力硬件、GPU/互联、训练与数据中心的影响

4.1 长程 Agent 的基础设施画像

【独立推断】GDPx 的默认 8 小时预算与多轮工具调用，使工作负载不同于传统短对话。它包含连续的推理 Token、工具执行、文件/代码检索、环境快照、评估器调用和失败重试。可建模为 T_total = Σ(T_prefill + T_decode + T_tool + T_queue + T_verify + T_retry)。模型调用只占其中一部分；因此增加 GPU FLOPS 并不能保证端到端任务时延按比例下降。

RSI 案例的 21.2M Token 是待分析轨迹的总量，不是单次上下文长度。若需反复扫描海量轨迹，系统可采用分块检索、摘要索引、外部内存和 KV Cache 管理；由此产生大量 Prefill、间歇 Decode、工具等待和重复读取。这对 GPU/HBM 的压力可能与在线聊天差异很大，但本文没有给出 Token/s、KV 容量或真实 GPU 利用率，不能推算具体集群规模。

【独立推断】对 Agentic RL 基础设施，重要的不只是 GPU↔GPU Fabric，还包括 GPU↔CPU/工具/沙箱 的服务网络。若 8 小时任务的大部分时间花在 EDA 编译、仿真或工具等待，继续扩大单个 Scale-up Domain 可能不是最优投资。需要先测每阶段阻塞时间与关键路径。

4.3 对 HBM 与存储分层的启示

【独立推断】长程任务会产生热数据（当前推理 KV）、温数据（最近工具结果/中间状态）和冷数据（历史轨迹、日志、CAD 版本）。热数据适合 HBM，温数据可放 CPU DRAM 或缓存服务，冷数据放 SSD/对象存储；策略目标不是让所有 21.2M Token 永驻 HBM，而是降低重复 Prefill 与工具读取成本。实际需测 Cache Hit、Prefill 重算、PCIe/网络传输、内存分配与回收。

4.4 对芯片设计 AI Agent 的工程要求

【独立推断】Aria/Arcverex/Ergodex 三类任务对应不同产品边界：①架构/RTL/验证：规格 → Testbench → 断言/覆盖 → 反例；②PPA：STA → ECO → Placement/Route → DRC/LVS/IR → 复核；③系统级：AXI/Cache/NoC 的 Transaction ID、Backpressure、Recovery 与 Ordering。工程 Agent 的可靠性必须以“正确实现能通过、错误实现能抓到、修改后签核仍成立”为闭环，不能仅看 RTL 生成正确率。

以 AXI/UCIe/NoC 等互联芯片为例，值得构造具备可重复验证器的任务：跨多 Link 的事务映射保持、AW/W 独立到达、B/R 返回乱序、故障切换后不重放已完成写入、Buffer 共享引起的死锁等。这些是本报告提出的未来基准题目，不是 SemiAnalysis 已经公开测试过的任务。

4.5 对 RL 后训练算力需求的启示

【独立推断】环境越真实，Verifier 越昂贵。可用 Cost_per_success = (C_inference + C_environment + C_verifier + C_storage + C_retry) / P_success 估计单个有效成果成本。GDPx 展示的成本仅覆盖部分模型调用，不是完整 RL 训练成本。若某些 EDA 签核需上百分钟或 FPGA 资源，CPU/FPGA/存储可能比 GPU 更早成为并发瓶颈；因此 RL 集群需要把环境执行容量与 GPU Rollout 容量共同规划。

4.6 设计更好的评估：成功率、完成时间、违规率分离

【独立推断】应至少分开测量 P(success)、Time-to-success、Cost-to-success、P(policy violation) 和 Regression risk。GDPx 的对齐测试表明“拿到目标”可能同时违反授权边界；芯片设计任务表明“功能正确”也可能因 PPA/DRC/LVS 失败而不可交付。面向生产系统，建议引入工程签核门槛和授权规则作为独立维度，而不是合成一个未经解释的综合分。
