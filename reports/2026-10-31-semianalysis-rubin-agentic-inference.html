02｜原文翻译与按结构中文转述

版权边界：仅翻译标题、副标题、作者、日期、公开导语的核心含义、各公开章节标题及少量必要短语；以下主体为基于公开正文的原创中文转述，不是逐字翻译。原文含图表，本报告引用其可核对的公开数值，不复制原图；付费续篇不作推测。

2.1 开篇导语｜六种硬件协同设计与首次 AgentX Rubin 结果

导语核心含义译述：Rubin 的设计不应只看 GPU，而应将 Rubin GPU、Vera CPU、NVLink 6 Switch、ConnectX-9、BlueField-4 与 Spectrum-6 视为面向智能体时代的协同平台。作者称这是其首次公开的 Rubin AgentX 实测，即使软件仍处于预发布阶段，也已呈现显著的系统级收益。

作者先引用 NVIDIA GTC 2026 的性能/功率宣传，再用 InferenceX 的测试对比提出：官方 3× 性能/MW 的表述可能偏保守，在某些相同交互速度目标下测得最高约 7×。随后将这一差异延伸为数据中心每 GW 利润可能增长的判断，并预期随着编译器、Kernel、Serving Engine 成熟，Rubin 的性能前沿仍会改善。注意“最高”“特定目标”和“预发布软件”三个限定条件，不能把最大值视为所有负载的稳定收益。

作者解释 AgentX 是对真实 Agent 会话特征进行重放的基准；其团队表示与多家云厂商、模型开发商及开源推理框架合作，并公开 InferenceX 工具。该合作与“验证”范围并不完全相同，不能把列出的每家机构都视为独立复现了本文的每项 Rubin 数据。

2.2 Agentic Workload Primer｜智能体工作负载入门

作者将 Agentic 负载概括为四个同时存在的特征。多轮会话可能包含几十至上百次交互；长上下文来自持续累积的历史、系统提示词及工具定义；高前缀复用使上轮已有 KV Cache 可被下轮继续利用；子智能体突发则产生大量短生命周期、上下文不同的并发请求。

关键并非所有 Agent 都具有极高 Decode TPS，而是同一个服务必须同时处理大量复用前缀的长会话、少量新增 Prefill、突发新 Prefill 和持续 Decode。缓存是否命中、缓存能否留在本地、子任务并发峰值多高，都会改变硬件利用率及瓶颈。原文特别注明：高复用成立的前提是有足够存储来保留 KV 张量。

2.3 Rubin Amazing Performance per TCO｜Rubin 单位总拥有成本的推理性能

作者以“每美元 TCO 对应的总 Token 数”作为性能—成本前沿纵轴，并将同一工作负载下的输出吞吐与拥有或租赁成本相结合。拥有场景覆盖服务器、网络 CapEx 摊销、机房、电力、资金成本；租赁场景使用三年承诺价。两种成本口径不可混用。

文章最醒目的 67× 出现在 170 TPS P90 interactivity、TRTLLM NVFP4 Dense、Rubin NVL72 与 GB300 Dynamo TRTLLM、hyperscaler owning TCO 的组合。作者随后明确指出，在服务商更常采用的 60–100 TPS 区间，Rubin 对其所列 GB300 TRTLLM 配置的收益约为 1.4–3×，远低于标题数字。

文章采用的 Rubin 机架 SKU 条件包括每计算托盘 2300W TDP 与 1.5TB Vera CPU LPDDR5X；这些是该实验的配置条件，不应自动推广到所有 Rubin SKU。文中比较 Rubin TRTLLM 与 GB300 的不同软件配置，并提示 SGLang 在 GB300 上可能实现接近 Rubin 的最高交互速度。

作者还给出 Rubin 相对 GB300 Dynamo TRTLLM 的最高 P90 interactivity：276.24 对 171.53 TPS，比值约 1.61×；但这是不同于固定 SLA 下吞吐/TCO 的另一指标。另在 2026 年 7 月租赁假设中，Rubin 的三年租赁报价超过 $8.5/GPU·h，Blackwell Ultra NVL72 约 $5/GPU·h；在 80 TPS 目标下，作者估算 Rubin 同租赁成本可产生约 62% 更多 Token。这些均是当时的市场价格与软件快照，不能当作长期报价。

端到端延迟的比较同样依赖所选吞吐/TCO 点：作者列举在 60 million tokens per dollar TCO 的点位，Rubin P90 E2E 约 20s，而 B200/B300 vLLM 约 60s；在另一个 160 million 点位分别约 20s 与 120s。P90 interactivity、TTFT、P90 E2E 不能相互替代，服务商应同时报告。

2.4 Rubin Performance per Watt – Jensen Sandbagging Performance Again｜每瓦性能与官方宣传差异

作者转向机房功率上限，使用“固定 P90 interactivity 目标下的总 Token 吞吐 / Utility MW”衡量每兆瓦产能。其核心发现是，性能领先幅度沿着延迟—吞吐 Pareto 曲线变化很大，而不是一个固定倍数。

在 100 TPS 目标下，文章给出 Rubin、GB300 Dynamo SGLang、GB300 Dynamo TRTLLM 三组图表读数约 59.4 / 28.5 / 21.1，相对较强 GB300 SGLang 为 2.09×；MI355X SGLang 的读数为 2.01，相应比值约 29.5×。在 150 TPS 下，Rubin 相对 GB300 SGLang 约 7.2×；200 TPS 下缩小到约 2.72×。

量纲核验警示：公开正文将上述图表数值描述为“million total tok/s/MW”。对万亿参数模型而言，字面单位与物理计算量之间存在明显疑问；在缺少原始 CSV、完整计量定义和可复现计算之前，本报告仅引用 59.4/28.5/21.1 等原文图表读数及相对比值，不将其解释为已经核实的绝对 tok/s/MW。请优先回到 InferenceX 原始 dashboard 核对归一化单位。

文章还强调 170 TPS 处的巨大差异：对 GB300 TRTLLM 的功率归一化比值约 62.9×，但若对照 GB300 SGLang，则仅约 5.56×。这说明比较对象的 Serving Engine 与性能前沿端点位置，对所谓“硬件倍数”具有决定性影响。

随后作者引入 DSX MaxLPS：利用推理负载未持续消耗满 TDP 的特点，通过动态功率分配降低闲置预留功率，让同一供电容量容纳更多计算资源。文章将此视为硬件设计、功率管理与数据中心运营共同优化的一环，而不是 Rubin 单芯片的 FLOPS 增益。

2.5 Annual Revenue and Profit per Gigawatt – The More You Buy, The More You Earn｜每 GW 年收入与利润

作者将固定电力容量转化为商业收益模型。使用约 1.6T 参数的 DeepSeek V4 Pro 作为 O(1–3T) 大模型代理；文中说明发布时已有 DeepSeek V4.1 Flash，但为比较大模型系统仍保留旧模型负载。模型授权费设为零，另设 75 TPS 交互目标、60% 利用率，并使用作者自己的 Token 定价、拥有成本及功率假设。

该情景下，作者模型给出 Rubin 每 Utility GW 年收入 $159.5B、模型利润 $149.9B；GB300 Dynamo SGLang 分别为 $114.9B、$105.3B，即约 +39% 收入与 +42% 利润。同样假设下，10MW 线性缩放的年模型利润差约 $446M。作者认为 Rubin 也可以通过约 28% 的价格折让来保持 GB300 的单位功率收入，而不必全部转化为利润。

不能把标题副标题中的“2×利润/GW”当作上述 75 TPS 情景的结果。公开详细模型在该条件下是 149.9/105.3≈1.42×。文章开篇“超过 2×”属于其他工作点或概括性作者估算；公开部分没有给出足以统一所有工作点的完整收益模型。

04｜技术机制：对 GPU、HBM、互联、推理架构与数据中心的影响

4.1 Agentic 流量如何改变推理系统的瓶颈？

【独立推断】传统单轮问答常将长 Prefill 和持续 Decode 作为主要阶段；Agentic 则形成“长会话缓存复用 + 工具调用停顿 + 多子 Agent 突发”的混合流量。系统可能出现 GPU 计算并不满载、KV Cache 却长期占用 HBM，或 GPU 瞬时满载但平均功率远低于 TDP 的情况。对同一请求，缓存命中率可决定 TTFT 与 Prefill 成本，Decode batch决定权重带宽摊销，EP/TP 通信决定 Scale-up 依赖。

会话时间线：新 Prompt → Prefill → Decode → Tool Call → KV 保留/转移 → 增量 Prefill → Decode → 并发 Sub-Agent → Join/Resume

【独立推断】一个粗略 KV 容量模型为 KV bytes ≈ 2 × 层数 × KV Heads × Head Dim × 每元素字节数 × 缓存 Token 数（单份、未考虑 MLA、量化、分页、TP 分片和跨层优化）。高前缀复用能节省计算，但不会免费消除 KV 的容量占用与管理开销。

4.2 Scale-up NVLink 6 与 Scale-out 的工作边界

【一手事实】NVIDIA 2026-03-16 官方发布说明 NVL72 由 72 颗 Rubin GPU、36 颗 Vera CPU 构成，使用 NVLink 6 实现机架内高速互联，跨机架使用 Quantum-X800 InfiniBand 或 Spectrum-X Ethernet，并通过 ConnectX-9 与 BlueField-4 连接系统与基础设施。该信息验证了平台组成，不能直接证明本文 AgentX 性能增益全部由 NVLink 6 带来。

【独立推断】TP 的 All-Reduce/All-Gather、MoE 的 Dispatch/Combine 与流水线并行激活传输，分别对带宽、延迟、突发和同步提出不同要求。若将高频小消息 Collective 放到高延迟跨机架链路，可能导致每层通信放大；相反，P/D 分离后的大块 KV 迁移可能容忍更高传输时延，但需要吞吐、拥塞控制和缓存调度共同配合。NVLink Domain 的最优规模不能从 67× 的 TCO 图反推，必须获取真实通信 Trace。

Ring All-Reduce（近似每 GPU 传输量）≈ 2 × (P−1)/P × 张量字节数；
MoE Dispatch/Combine 的一阶流量 ∝ 活跃 Token 数 × Hidden Size × 路由副本数 × 元素字节数（需考虑 EP 映射、是否本地 Expert、Combine 与重排开销）。

这两个模型仅用于识别敏感参数，不能替代 NVLink 6 交换拓扑、包长、Buffer、路由和链路利用率的实测。

4.3 HBM、CPU LPDDR 与 KV 层次化存储

【原文事实】本次测试使用的 Rubin SKU 每计算托盘配置 1.5TB CPU LPDDR5X，作者把该配置作为 TCO 和性能评估边界之一。这不意味着 1.5TB 全部可作为 GPU KV Cache 直接等速访问。【独立推断】在多轮 Agent 场景，HBM 热 KV、CPU 内存温 KV、远端存储冷 KV 的分层策略可能改变所需 GPU 数量及 P90 TTFT；需要单独测量 Prefetch、PCIe/NVLink-C2C、DMA 与跨节点网络开销，才能判断存储层次的实际收益。

4.4 从吞吐性能转向可售卖 Token 与 SLA

【独立推断】单个 Kernel 的峰值算力不是推理运营商的最终目标。可售卖 Token 取决于多目标约束：TTFT、P90 ITL、P90 E2E、有效利用率、缓存命中、价格与成本。高 TPS 交互目标会改变可容纳的 Batch 和并发，从而改变硬件性价比排序。

吞吐/成本 = (单位时间有效 Token 数) / (同一时间口径的全部拥有或租赁成本)
吞吐/Utility MW = (单位时间有效 Token 数) / (含配电/冷却等的实际功率)
模型利润 = Token 计费收入 − 计算、网络、供电、机房及运营等成本（需明确口径）

原文的每 GW 利润属于商业模型：若需求不足、Token 价格下降、实际利用率低于 60%、软件优化追平，结论会显著改变。+42% 是同一模型条件下的相对结果，不是硬件采购后自动获得的净利润。

4.5 DSX MaxLPS：为什么网络设计也要考虑动态功率？

【一手事实】NVIDIA DSX MaxLPS 文档解释了其工作路径：设施/站点功率约束 → Dynamic Power Software 结合机架遥测计算可用余量 → 经 BMC/Redfish 下发 GPU 功率限制；软件控制环通常以数秒为周期，毫秒级尖峰仍由硬件和电气保护处理。其目标是减少预留但未使用的电力，并非让 GPU 永远满功率。

【独立推断】对交换芯片及 NIC，动态功率密度提升可能带来更高的机架平均网络吞吐、突发聚集和故障域密度。因此网络规划不能只以静态 TDP 或平均 Token/s 推算，还需验证 网络峰值/平均比、EP incast、PFC/ECN 反应、交换 Buffer、功率调整后的通信同步。电力容量固定不意味着网络容量需求固定。

4.6 对 100T Scale-up Switch 与 P/D 架构的直接启示

【独立推断】评估 TH6、UALink、NVSwitch 或其他高 Radix Scale-up Fabric 时，应以同一模型、同一 P90 SLA、同一并行策略和相同成本/功率口径比较，而不是只用 Tbps、端口数或 bisection bandwidth。下一步最好同时采集 GPU Kernel Trace、NIC/Fabric Telemetry、KV Cache Hit/Miss、TTFT、P90 ITL、P90 E2E，建立通信导致的计算空泡（stall）归因。

6.1 优先级最高的五个核查问题

Q1｜67× 是否主要是性能前沿端点效应？ 在同一 60、80、100、150、170、200 TPS 下，统一 GB300 SGLang/TRTLLM 与 Rubin TRTLLM 的模型、FP4 格式、KV Cache、批量、功耗和成本，画全 Pareto 曲线。重点复核 170 TPS 处 62.9× 与 5.56× 的巨大差异。

Q2｜“million total tok/s/MW”的原始单位是什么？ 下载或导出 InferenceX 的原始测试点、归一化脚本及图表元数据，核对是否为每 GW、每秒、每时段累计 Token，或数据展示口径有误。未核实前不将绝对值用于容量规划。

Q3｜每 GW $149.9B 年模型利润的敏感性如何？ 固定相同电力与 P90 SLA，分别调整利用率 30%/60%/85%、输出 Token 价格、机架采购价、资金成本、PUE 与缓存命中率，检验收益排名及利润绝对值是否稳定。

Q4｜NVLink 6 真正带来多少收益？ 在相同 Rubin GPU 上对比 TP/EP 分组、跨 Rack KV Transfer、All-to-All 延迟分布、Collective stall、NVLink 与 NIC 带宽利用率。分离 GPU 计算、软件栈和互联网络的贡献。

Q5｜MaxLPS 与 Fabric 的动态联动如何设计？ 采集秒级 GPU 功率与毫秒级通信突发，验证限功率对 Token 延迟、通信峰值及交换 Buffer 的影响，并核实功率遥测的时间同步。
