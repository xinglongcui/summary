TPUv7 Ironwood 与 AgentX：Google TPU 如何争夺推理性价比

2. 标题、导语及公开正文结构化中文转述

标题译文：《Ironwood 王座之争：Google TPU 争夺推理市场》。副标题要旨：CUDA 生态壁垒是否出现可行替代；NVIDIA 对标优化；Kimi K3、Muse Spark Open、GLM-5.3、TorchTPU、SGLang、vLLM、llm-d 与 Ray 的共同演进。

导语要旨：作者认为 TPU 对外供给及开源推理框架适配正共同削弱 CUDA 的独占优势。本文发布 TPUv7 在四类模型上的 AgentX 多轮、长上下文推理结果。须区分作者对客户采用情况的陈述、可复现实测提交，以及作者对竞争格局的判断。

Recommendation to Jensen｜对 NVIDIA 的建议

作者认为 NVIDIA 在某些开源项目反馈与功能合入方面速度偏慢，TPU、AMD 团队则通过提供硬件与贡献上游代码加快适配。关于公司内部流程和工程师行为的描述主要属于作者观察与评价，不宜当作可独立证实的行业事实。

Meta’s Muse Spark Open FP4 816B on SGLang TorchTPU｜Muse Spark Open

作者称 TPUv7 在一个针对 GPU 优化的 816B 模型上达到有竞争力的 Decode 性价比，但 Prefill 端到端时延仍需优化。SGLang 使用融合 Megakernel 减少启动间隙，并以 HiCache、TPU-Sync 将缓存卸载至 CPU DRAM。该模型 head_dim=64，作者认为 TPU 矩阵阵列填充效率不理想，展示了模型形状与硬件阵列的耦合。

GLM5.2/5.3 vLLM AgentX FP8｜稀疏注意力与缓存

GLM-5.2/5.3 为 MoE 模型，文章列出 744B 总参数、约 39B 激活参数；其 DSA 索引器从长历史中选取 2,048 个条目做完整注意力。文章描述四项优化：按序列位置切分的 Decode Context Parallelism（DCP）、SparseCore 的不规则 Gather、129B key/scale 布局重排以避免按 256B 对齐造成浪费，以及路由/专家/All-reduce/Attention merge 融合并补充 4/8 Token 小形状。FP8 同精度比较有利于 TPU，但 FP4 GPU 在若干负载仍领先。

Qwen3.5 397B AgentX｜分离式服务与路由

AgentX 包含多轮会话、长上下文、前缀重用、子 Agent 突发四类负载特征。llm-d 将 Prefill/Decode 分布在不同主机，文章配置每个主机 4 颗 TPUv7、合计 24–32 颗芯片；限制 Decode 主机并发，平衡队列等待与每用户生成速率。Qwen3.5 含 45 层线性注意力与 15 层全注意力；优化包括 Decode Megakernel、Host DRAM KV/状态卸载、Cache-aware Routing。文章称精确 DP rank 路由令 Decode Cache Hit 从 56% 升至 76%。

Kimi K3 AgentX｜Megakernel 与 DCP

作者说明 Kimi K3 的 MLA 将各头 KV 压缩为共享 latent，简单沿 Head 维切分会复制缓存，因此使用按 Token 位置划分的 DCP。Megakernel 融合多层前向、预取下一层权重；vLLM 继续负责调度、前缀缓存和 KV 传输。作者报告 TPUv7 发布初期接近 GB300 FP4 性价比，但后续 NVIDIA 多轮优化反超。Rubin 的对比属于跨代、且预览提交，不可视为公平实测。

4. 技术机制与系统架构影响

KV 与内存层级：Agentic 多轮前缀复用使 KV Cache 容量与命中率影响单位 Token 成本；Host DRAM Offloading 降低 HBM 容量压力，却增加 Host↔加速器链路带宽、PCIe/专用互联、拷贝与预取时序需求。应分别测量 cache hit、miss penalty、prefetch overlap 和 P99 TTFT。

Scale-up 通信：DCP 将序列位置分布到多芯片，避免 MLA KV 全量复制；代价是每层部分 Attention 结果归并。EP 的 Expert Dispatch/Combine 与 All-reduce 也可能成为互联瓶颈。判断网络需求应依据每 Token 的跨芯片字节量、Collective 次数、并发和峰值突发，而非只看峰值带宽。

算子融合与计算利用率：Decode 小 Batch 容易受 Kernel Launch、HBM 权重读取和小形状填充影响。Megakernel 降低 launch gap，但可能增加寄存器压力、调度复杂度和动态形状处理成本。模型与硬件 co-design 体现在 head_dim、稀疏 Gather、KV 布局和固定 Shape 编译。

P/D 分离：Prefill 与 Decode 分置可降低长 Prefill 对 Decode 的干扰，但 KV 迁移、队列和 Session Sticky Routing 必须联合设计。仅优化 Decode tok/s/user 不代表端到端优胜；应联看 TTFT、TPOT、P90/P99、Token/$、质量以及实际租赁价格。

5. 事实、判断与独立推断分离

【原文明确事实/陈述】官方文章发表于 2026-11-05；公布四类 AgentX 模型的 TPUv7 提交数据；描述 DCP、SparseCore、Megakernel、TPU-Sync、llm-d 及 Cache-aware Routing。这里的“明确”仅表示原文写明，不代表第三方独立证实。

【作者预测/判断】TPU 生态将成为 CUDA 的重要替代；NVIDIA 某些模型/精度组合难以追回 TPU；TPUv8 FP4 将改变竞争格局；NVIDIA 组织流程需要改革。这些不是既成事实。

【独立推断】推理架构竞争正在从单芯片算力扩展到“模型形状 × Kernel × KV 层级 × 路由 × 互联 × TCO”的联合优化；对网络芯片规划，需以 KV Miss 突发与 DCP/EP Collective 的 tail latency 建模，而不能直接把文章性价比倍数转成交换机端口需求。此结论需要真实生产流量验证。

6. 值得验证的问题与一手来源

① InferenceX/AgentX 提交是否可复现？固定模型版本、精度、质量门限、硬件租赁价、TTFT/TPOT SLA 与提交日期，重跑 TPUv7、GB300、MI355X。
