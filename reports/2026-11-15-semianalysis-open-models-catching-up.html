2. 原文翻译与按章节中文转述

标题：开放模型正在追赶闭源模型吗？副标题：跨越前沿模型发展的不同时代比较开放与闭源模型：差距正在缩小吗？

导语：作者认为近两个月开放模型在编码和 Agent 任务上取得突破。GLM 5.3、Kimi K3 已可处理大量过去由闭源前沿模型占据的任务。作者提出经济问题：若开放模型以更低价格保持接近的能力，模型服务是否会商品化？为了预测未来，文章先回顾历史，认为不能用同一组基准跨时代比较，因为基准会饱和并逐渐失去区分能力。

How we measured｜如何测量：文章把 LLM 历史分成早期 Scaling、Reasoning、Agentic 三个时代，各自选取当时具有代表性的模型与基准，按时代内最佳成绩归一化到100，再做等权综合评分。主要使用 Prime Intellect 的评测栈与 Prime-RL harness，部分数据来自 Artificial Analysis 和 DeepSWE 榜单。开放模型按发布时可用的 vLLM、硬件和模型卡采样配置运行；闭源模型用固定 API 版本。模型选择、基准组合和权重具有主观性，跨时代的分数不能直接比较。

Era 1 | Early scaling (2022–2024)｜早期规模化：作者选择 GSM8K、HumanEval、TriviaQA、MMLU-Pro，描述当时以短题数学、单函数代码与知识题为主的能力竞争。2023年 Llama-2-70B 综合39.9，GPT-3.5 Turbo为75.7；2024年7月 Llama-3.1-405B达到86，追过先前 GPT-3.5 的能力水平；2024年12月 DeepSeek V3为94.1，接近 GPT-4o的95.5。此处“追上”指文章特定综合指标，而非所有真实应用同等表现。

Era 2 | Reasoning (2024–2025)｜推理时代：o1 让旧基准不足以区分模型，评估转向 AIME、Humanity's Last Exam 等推理任务。作者给出的初始开放/闭源综合差距为12.1分（上一时代初期为35.8分）；DeepSeek R1 缩小差距，2025年5月 R1-0528 综合达到78，作者计算从新一轮前沿出现到开放模型追上原起点约8.5个月。作者同时提醒 HLE 等基准存在缺陷。

Era 3 | Agentic (2025–Today)｜智能体时代：文章强调 Claude Code 的模型与 Harness 组合价值，评价转向 Terminal-Bench 2.1、BrowseComp-Plus、τ³-banking、DeepSWE 等长任务基准。作者称 Kimi K2.6 在4.8个月后超过 Opus 4.5 的基准综合水平（56.3），GLM-5.2 在6个月后超过 GPT-5.2 的对应水平（72.4）。文中给出前沿模型发布平均间隔从前两时代213天、120天压缩到51天。此为作者选取模型、区间和评分规则下的统计，不是全行业普适规律。

Looking forward｜展望：作者明确反对把 benchmark 分数等同于产品价值：即便 Kimi K3 在其选定组合中超过 Fable 5，作者日常仍偏好 Fable，因为 Claude Code 等完整产品的体验更好；公开基准还容易被针对性 RL 环境训练而过拟合。作者也讨论闭源模型安全测试/发布时间可能影响表面追赶周期，不能简单把发布日期差解释为研发能力差。

The Upcoming Era｜即将到来的时代：只有标题公开，正文进入付费墙；不分析其预测。

3. 核心论点与关键数据

核心命题：开放与闭源模型的能力差距具有“新范式突破→闭源领先→开放复现→差距收敛”的周期性。作者发现其三时代样本中的追赶时间逐步缩短，但这个趋势依赖“追上旧时代起点”的定义。

4. 技术机制及对 AI 算力系统的影响

训练与推理算力：追赶周期缩短并不意味着训练成本同比例下降。开放模型可能利用知识蒸馏、算法公开、RL、数据工程和更高效的 MoE 实现能力复制；文章没有提供各模型训练 FLOPs、GPU 时数和 HBM BOM 的统一口径，不能推导“开放模型训练便宜几倍”。

推理架构：Agentic 工作负载从短问答转向多轮工具调用、长上下文和状态复用；同等基准成绩下，端到端成本仍受 TTFT、ITL、KV Cache 命中、Prefix Caching、P/D Disaggregation、路由和 Harness 重试次数影响。开放模型若能在自建推理集群运行，将使用户在模型/API价格、数据驻留、定制推理栈之间有更多选择。

GPU、HBM与网络：若开放模型推理需求增长，GPU需求不必然下降：Token 单价下降可带来需求弹性。更长 Agent 会话增加 KV/HBM/DRAM 需求；MoE Expert Parallel、Tensor Parallel 与跨节点 KV 传输可能增加 Scale-up/Scale-out 压力。这些是独立工程推断，不是文章实测。

系统采购建议：比较开放/闭源方案时，应同时固定任务完成率、重试次数、每成功任务 Token 数、SLO、硬件折旧和 GPU 利用率，不能只看公开 benchmark 分数或每百万 Token 标价。闭源 API 的 Harness、工具集成、模型更新速度可能抵消裸模型分数差异。

5. 事实、作者判断与独立推断

【原文明确事实（文章披露）】作者使用三个时代、不同基准、时代内最佳分100、等权平均的研究设计；列出了模型分数和发布时点；使用 Prime-RL 等评测工具；公开正文明确承认 benchmark 的局限。这些是文章所报告的方法与结果，不代表本报告已独立复现实验。

【作者预测/判断】开放模型追赶周期逐代约减半；未来仍会出现前沿闭源突破与开放模型追赶；闭源商业护城河不会仅因开放模型分数接近就立即消失；Agent 产品化与 Harness 能力对真实体验至关重要。

【独立推断】硬件需求将由模型数量、Token 消费弹性、每任务总 Token 和缓存/网络结构共同决定；开放模型生态成熟可能扩大自建 GPU 推理集群市场，但不能从这篇文章直接推出 GPU/HBM 市场规模预测。

【关键反例】某开放模型在四个基准上追平闭源旧版本，却可能在多轮鲁棒性、工具调用、运维 SLA、隐私审计和生产成本上落后；反过来，经过针对性优化的开放模型也可能在某个垂直任务优于综合评分更高的闭源模型。

6. 值得验证的问题与一手资料

① 追赶时间的定义：文章是追上“时代初期闭源模型”，而非追上“同一天最新闭源模型”。应同时绘制按发布日期的绝对能力差与相对旧版本追赶时间，避免把移动前沿误读为已经消失的能力差。

② 评测可复现性：核对模型版本、采样、推理引擎、硬件、pass@k、环境镜像与失败重试。Prime-RL 官方代码、Prime Intellect、Artificial Analysis。

③ 基准污染与可靠性：检查 HLE、SWE-bench Pro 等公开争议及污染防护，加入私有生产任务、盲测和真实用户偏好。SWE-bench 项目、过程监督研究。

④ 工程与经济性：针对 Agentic Coding 比较任务成功率、端到端延迟、每成功任务美元、KV驻留与工具调用数；模型分数不应替代真实任务总成本。

⑤ 一手核验：SemiAnalysis 原文（How we measured、Era 1–3、Looking forward）。需另查各模型发布公告与 model card 以验证版本及日期；当前报告没有把所有模型的官方发布公告逐一核实。
